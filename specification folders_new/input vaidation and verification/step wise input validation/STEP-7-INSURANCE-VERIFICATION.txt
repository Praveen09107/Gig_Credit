SYSTEM DESIGN PROMPT — STEP-7: INSURANCE VERIFICATION
GigCredit Onboarding | Version: Final | Pillar: P6 Financial Resilience
===========================================================================

PURPOSE
-------
Step-7 verifies the user's insurance coverage. Insurance participation
strengthens financial responsibility signals and improves risk assessment.
Three insurance types are supported:
  1. Health Insurance
  2. Vehicle Insurance
  3. Life Insurance

All insurance inputs are optional, EXCEPT Vehicle Insurance, which becomes
REQUIRED if the user selected "Yes" for Vehicle Ownership in Step-1.

Validation architecture:
  - OCR Extraction       : On-device
  - API Verification     : Government simulation (FastAPI + MongoDB)
  - Individual Validation: OCR vs API data (per field)
  - Cross-Internal       : Within document fields (consistency)
  - Global Validation    : Consistency with previous steps


===========================================================================
HOW IT IS PRESENTED ON SCREEN
===========================================================================

Three insurance cards displayed vertically.
Each card shows:
  - Insurance type name
  - Brief description of what it covers
  - Estimated score impact

Vehicle insurance card mandatory status is dynamically set based on
Vehicle Ownership answer from Step-1.

===========================================================================
UI GATE RULES
===========================================================================

GATE 1 — Vehicle Insurance Card Badge (dynamic from Step-1):
  verified_profile.has_vehicle = true
    → Card shows "REQUIRED" badge
    → Upload is mandatory
    → Missing = incomplete step

  verified_profile.has_vehicle = false
    → Card shows "OPTIONAL" badge
    → Upload not required
    → Skipping has no penalty

GATE 2 — Continue Button:
  has_vehicle = true  → vehicle insurance must be uploaded and pass
                        all validations before Continue is enabled
  has_vehicle = false → Continue available at any point (all 3 optional)

GATE 3 — RC Deduplication (Step-5 cross-dependency):
  IF verified_profile.work.rc_verified = true (Step-5A completed):
    → RC verification SKIPPED in Step-7
    → System reuses vehicle_number from Step-5 global state
    → Vehicle insurance OCR vehicle number cross-checked against
      Step-5 vehicle number
  IF step5_skipped = true OR rc_verified = false:
    → Normal RC verification flow applies in Step-7

#  | Field                    | Rule                            | Blocking
---|--------------------------|----------------------------------|----------

2  | Policy Holder Name       | OCR vs API fuzzy >= 85%          | HARD FAIL
3  | Insurance Company        | OCR must match API               | HARD FAIL
4  | Policy Start Date        | Must be valid date format        | HARD FAIL
5  | Policy Expiry Date       | Valid date; API status = Active  | HARD FAIL
6  | Sum Insured              | Must be numeric > 0              | HARD FAIL
7  | Premium Amount           | Must be numeric > 0              | HARD FAIL

--- CROSS-INTERNAL VALIDATION — HEALTH INSURANCE ---

#  | Check                                          | Rule               | Blocking
---|------------------------------------------------|---------------------|---------
1  | Policy number consistent across document       | Identical in all   | HARD FAIL
   | sections                                       | sections           |
2  | Policy holder name consistent across document  | Same in all name   | HARD FAIL
   |                                                | fields             |

--- BANK TRANSACTION CROSS-CHECK — HEALTH INSURANCE ---

Premium debit matching in Step-3 canonical CSV:
  Amount   : premium_amount (OCR) ± 5%
             OR annual_premium ÷ 12 (if monthly mode) ± 5%
  Merchant : contains insurer name keywords
             e.g. "STAR HEALTH", "HDFC ERGO", "NIVA BUPA",
                  "CARE HEALTH", "ICICI LOMBARD", "HEALTH INSURANCE"
  Category : INSURANCE_PREMIUM

  Match found → health_premium_bank_verified = true  (bonus P6 signal)
  No match    → health_premium_bank_verified = false  (soft flag, non-blocking)

  Note: Step-3 bank statement is converted to a canonical CSV format.
  Each transaction has: date, amount, merchant, category, transaction_id.
  Matching uses: transaction date ± 7 days of premium due date AND
                 amount within ± 5% tolerance.

TECHNICAL FLOW — STEP-7
===========================================================================

User opens Step-7
  ↓
System reads verified_profile.has_vehicle from Step-1
  ↓
Three insurance cards rendered with correct badges (REQUIRED / OPTIONAL)
  ↓
[HEALTH INSURANCE — Optional]
  User uploads Health Insurance Policy Document
    → OCR: policy_number, holder_name, company, start_date,
            expiry_date, sum_insured, premium_amount, scheme_desc
    → POST /gov/insurance/health-policy-verify
    → Individual validation: all 8 OCR fields validated (see table)
    → Cross-internal: policy_number + holder_name consistent
    → Bank cross-check: premium debit in Step-3 CSV (± 5%, ± 7 days)
    → Global: holder_name vs Step-1 name AND Step-2 Aadhaar name
    [PASS] → health_insurance = true
    [FAIL] → card shows error; user can retry; step not blocked
  ↓
[VEHICLE INSURANCE — Mandatory if has_vehicle = true]

  GATE: IF rc_verified = true from Step-5A:
    → Skip RC API, reuse vehicle_number from global state
  ELSE:
    → User uploads RC Book
    → OCR: vehicle_number, owner_name, vehicle_class,
            registration_date, engine_number, chassis_number
    → POST /gov/vehicle/rc-verify
    → RC Individual validation: all 6 fields (see table)
  ↓
  User uploads Vehicle Insurance Policy
    → OCR: policy_number, vehicle_number, owner_name, company,
            start_date, expiry_date, premium_amount,
            chassis_number, engine_number
    → POST /gov/insurance/vehicle-policy-verify
    → Individual validation: all 9 fields (see table)
    → Cross-internal: vehicle_number, chassis_number, engine_number
                      consistent across RC + insurance
    → Bank cross-check: premium debit in Step-3 CSV
    → Global: vehicle_number vs Step-5 vehicle_number (if applicable)
    [PASS] → vehicle_insurance = true
    [FAIL] → HARD FAIL if has_vehicle = true (blocks Continue)
  ↓
[LIFE INSURANCE — Optional]
  User uploads Life Insurance Policy or Premium Receipt
    → OCR: policy_number, holder_name, company, sum_assured,
            total_premium_paid, issue_date, coverage_period,
            coverage_status, payment_mode, coverage_name
    → POST /gov/insurance/life-policy-verify
    → Individual validation: all 9 fields (see table)
    → Cross-internal: policy_number + holder_name consistent
    → Bank cross-check: premium debit in Step-3 CSV (± 5%, ± 7 days)
    → Global: holder_name vs Step-1 name AND Step-2 Aadhaar name
    [PASS] → life_insurance = true
    [FAIL] → card shows error; user can retry; step not blocked
  ↓
Update verified_profile.insurance
  ↓
Step-7 Status = COMPLETED
Enable navigation to Step-8
