SYSTEM DESIGN PROMPT — STEP-6: GOVERNMENT SCHEME VERIFICATION
GigCredit Onboarding | Version: Final (Updated) | Pillar: P7 Social Accountability
===========================================================================

PURPOSE
-------
Step-6 collects optional government scheme registrations and financial
security programs associated with the user. These schemes strengthen
financial credibility and improve scoring signals under the P7 (Social
Accountability) pillar and cross-feed P2 (Payment Discipline) and
P3 (Debt Management).

All schemes in this step are OPTIONAL globally.
If a user selects any scheme, that scheme's ID and proof upload become
CONDITIONALLY REQUIRED. Invalid inputs are rejected and ignored.

Supported Schemes (6 total):
  Scheme 1 : eShram Worker Registration
  Scheme 2 : PM-SYM (Pradhan Mantri Shram Yogi Maandhan)
  Scheme 3 : PMJJBY (Pradhan Mantri Jeevan Jyoti Bima Yojana)
  Scheme 4 : PMMY (Pradhan Mantri Mudra Yojana)
  Scheme 5 : PPF (Public Provident Fund)
  Scheme 6 : Udyam / MSME Registration  ← NEW (previously missing)

Validation architecture:
  - Individual Validation : Per-field rules on user-entered data + OCR
  - API Verification      : Government simulation (FastAPI + MongoDB)
  - Bank Cross-Check      : Scheme payments matched against Step-3 CSV
  - Cross-Internal        : Consistency within scheme documents
  - Global Validation     : Identity cross-check with Step-1, Step-2, Step-3


===========================================================================
HOW IT IS PRESENTED ON SCREEN
===========================================================================

A checklist screen showing 6 scheme cards.
Each card shows:
  - Scheme name and short description
  - Estimated score impact
  - Expand button to reveal input fields

Unselected schemes remain collapsed and are skipped entirely.
The entire step is optional — user may skip all schemes.

Step-level message shown to user:
  "Each government scheme you are enrolled in adds to your
   Social Accountability score. Even 1–2 verified schemes
   can improve your final credit score by 15 to 30 points."


===========================================================================
SCHEME 1 — ESHRAM WORKER REGISTRATION
===========================================================================

Score impact: "Can add up to 12 points"

INPUTS:
  Input 1 : UAN Number (Conditional Required when scheme selected)
            Format  : 12-digit numeric
            Example : 123456789012
  Input 2 : eShram Card Upload (Conditional Required)
            Format  : JPG or PNG

UI BEHAVIOUR:
  UAN number entry → User clicks Verify
  If API succeeds → eShram Card upload enabled
  If API fails    → Error shown, scheme marked unverified


API VERIFICATION — ESHRAM
  Endpoint  : POST /gov/eshram/verify
  MongoDB   : eshram_db
  Request   : { "uan": "123456789012" }
  Response  : {
                "worker_name"          : "Ravi Kumar",
                "occupation"           : "Electrician",
                "state"                : "Tamil Nadu",
                "registration_status"  : "Active",
                "registration_date"    : "2022-06-15",
                "verified"             : true
              }
  Possible status: Active | Inactive | Not Found


OCR EXTRACTION — ESHRAM CARD
  Fields extracted:
    worker_name         : Name of registered worker
    fathers_name        : Father's name
    date_of_birth       : DOB of worker
    gender              : Male / Female / Other
    uan_number          : 12-digit UAN
    primary_occupation  : Work category
    aadhaar_reference   : Masked Aadhaar (last 4 digits)
    photo               : Worker photo on card


INDIVIDUAL VALIDATION — ESHRAM
  Field               | Rule                                          | Blocking
  --------------------|-----------------------------------------------|---------
  UAN Number          | Must be exactly 12 digits                     | HARD FAIL
                      | Numeric only                                  |
                      | Must not be all zeros                         |
  API Status          | registration_status must be Active            | HARD FAIL
  OCR Worker Name     | Must match API worker_name (fuzzy ≥ 85%)      | HARD FAIL
  OCR UAN Number      | Must match user-entered UAN exactly           | HARD FAIL
  OCR DOB             | Must be a valid date                          | Soft flag
  Aadhaar Reference   | Must show last 4 digits (XXXX-XXXX-ABCD)      | Soft flag


CROSS-INTERNAL VALIDATION — ESHRAM
  Check                                               | Blocking
  ----------------------------------------------------|----------
  UAN on card must match UAN entered by user          | HARD FAIL
  Worker name consistent across front and back of card| Soft flag


GLOBAL VALIDATION — ESHRAM
  Field               | Compared Against                | Blocking
  --------------------|----------------------------------|---------
  Worker Name         | Step-1 Full Name (fuzzy ≥ 85%)  | Soft flag
  Date of Birth       | Step-2 Aadhaar DOB (exact)      | Soft flag
  State               | Step-1 State of Residence       | Soft flag

Global profile update:
  verified_profile.gov_schemes.eshram = true
  verified_profile.gov_schemes.eshram_occupation = "Electrician"

SCHEME 2 — PM-SYM (PRADHAN MANTRI SHRAM YOGI MAANDHAN)
===========================================================================

Score impact: "Can add up to 10 points"

INPUTS:
  Input 1 : Pension Account Number (Conditional Required)
            Format  : Alphanumeric (e.g. PM-SYM-829201)
  Input 2 : Pension Card or Registration Certificate (Conditional Required)
            Format  : JPG, PNG, or PDF


API VERIFICATION — PM-SYM
  Endpoint  : GET /api/pension/status
  MongoDB   : pmsym_db
  Request   : {
                "aadhaar_number"         : "XXXX-XXXX-1234",
                "pension_account_number" : "PM-SYM-829201"
              }
  Response  : {
                "scheme"                 : "PM-SYM",
                "status"                 : "ACTIVE",
                "monthly_contribution"   : 100,
                "last_payment_date"      : "2026-02-10",
                "pension_account_number" : "PM-SYM-829201",
                "verified"               : true
              }
  Possible status: ACTIVE | INACTIVE | NOT_FOUND


OCR EXTRACTION — PM-SYM CARD
  Fields extracted:
    pension_account_number  : Unique subscriber ID
    subscriber_name         : Name on card
    date_of_birth           : DOB
    gender                  : Male / Female / Other
    pension_start_date      : Date enrolled
    monthly_contribution    : Amount (₹55 / ₹100 / ₹200)
    government_contribution : Matching govt amount
    aadhaar_reference       : Masked Aadhaar


INDIVIDUAL VALIDATION — PM-SYM
  Field                    | Rule                                      | Blocking
  -------------------------|-------------------------------------------|---------
  Pension Account Number   | Must match PM-SYM-XXXXXX format           | HARD FAIL
  API Status               | Must be ACTIVE                            | HARD FAIL
  OCR Account Number       | Must match entered account number         | HARD FAIL
  OCR Subscriber Name      | Must match API name (fuzzy ≥ 85%)         | HARD FAIL
  Monthly Contribution     | Must be ₹55, ₹100, or ₹200 (valid tiers) | Soft flag


CROSS-INTERNAL VALIDATION — PM-SYM
  Check                                                  | Blocking
  -------------------------------------------------------|---------
  Pension account number consistent across card sections | HARD FAIL
  Contribution amount must align with age-based tier     | Soft flag


BANK TRANSACTION CROSS-CHECK — PM-SYM
  Rule: Step-3 canonical CSV must show monthly debit
        matching contribution amount (± ₹5 tolerance)
  Date gap between consecutive debits must be ≤ 35 days
  If bank match found → pmsym_bank_verified = true (strong P2 signal)
  If no match        → Soft flag; scheme accepted as declared


GLOBAL VALIDATION — PM-SYM
  Field             | Compared Against               | Blocking
  ------------------|--------------------------------|---------
  Subscriber Name   | Step-1 Full Name (fuzzy ≥ 85%) | Soft flag
  DOB               | Step-2 Aadhaar DOB (exact)     | Soft flag

Global profile update:
  verified_profile.gov_schemes.pmsym = true
  verified_profile.gov_schemes.pmsym_contribution = 100

SCHEME 3 — PMJJBY (PRADHAN MANTRI JEEVAN JYOTI BIMA YOJANA)
===========================================================================

Score impact: "Can add up to 8 points"
Note: No verification API for PMJJBY. Validation via OCR + bank cross-check.

INPUTS:
  Input 1 : PMJJBY Insurance Certificate Upload (Conditional Required)
            Format  : JPG, PNG, or PDF


OCR EXTRACTION — PMJJBY CERTIFICATE
  Fields extracted:
    member_name           : Insured person's name
    master_policy_number  : Bank-issued master policy number
    urn                   : Unique Reference Number
    date_of_birth         : DOB of insured
    bank_account_number   : Linked savings account
    bank_name             : Issuing bank
    insurance_provider    : LIC or partner insurer
    date_of_commencement  : Policy start date
    cover_end_date        : Policy expiry date (31 May each year)
    sum_assured           : ₹2,00,000 (fixed)
    premium_amount_paid   : ₹436 per year (fixed)
    renewal_date          : Annual renewal date


INDIVIDUAL VALIDATION — PMJJBY
  Field                 | Rule                                        | Blocking
  ----------------------|---------------------------------------------|---------
  Member Name           | Must be readable; min 3 chars               | HARD FAIL
  Master Policy Number  | Must be readable and non-empty              | HARD FAIL
  URN                   | Must be readable and non-empty              | HARD FAIL
  Sum Assured           | Must be ₹2,00,000 (fixed — any other = fake)| HARD FAIL
  Premium Amount        | Must be ₹436 (fixed — any other = flag)     | Soft flag
  Cover End Date        | Must be 31st May of a valid year            | Soft flag
  DOB                   | Must be a valid date                        | Soft flag


CROSS-INTERNAL VALIDATION — PMJJBY
  Check                                              | Blocking
  ---------------------------------------------------|----------
  Policy start date must be before cover end date    | HARD FAIL
  Bank account number on cert must be readable       | Soft flag


BANK TRANSACTION CROSS-CHECK — PMJJBY
  Rule: Step-3 CSV must show annual debit of ₹436
        on or near policy renewal date (± 15 days)
  Merchant narration should contain: LIC / PMJJBY / JEEVAN JYOTI
  If bank match found → pmjjby_bank_verified = true


GLOBAL VALIDATION — PMJJBY
  Field               | Compared Against               | Blocking
  --------------------|--------------------------------|---------
  Member Name         | Step-1 Full Name (fuzzy ≥ 85%) | Soft flag
  Bank Account Number | Step-3 Verified Account Number | Soft flag

Global profile update:
  verified_profile.gov_schemes.pmjjby = true


===========================================================================
SCHEME 4 — PMMY (PRADHAN MANTRI MUDRA YOJANA)
===========================================================================

Score impact: "Can add up to 10 points"
Note: No verification API. Validation via OCR + bank cross-check.

INPUTS:
  Input 1 : Loan Account Number (Conditional Required)
            Format  : Alphanumeric
  Input 2 : Mudra Loan Acknowledgement / Sanction Letter (Conditional Required)
            Format  : JPG, PNG, or PDF
  Input 3 : Bank No-Due Certificate after loan closure (Optional)
            Format  : JPG, PNG, or PDF


OCR EXTRACTION — MUDRA LOAN LETTER
  Fields extracted:
    applicant_name     : Borrower name
    loan_amount        : Sanctioned amount (₹)
    loan_account_number: Unique loan account ID
    bank_name          : Lending institution
    loan_approval_date : Date loan was approved
    loan_type          : Shishu / Kishor / Tarun
    mudra_card_number  : 16-digit Mudra card (if issued)

OCR EXTRACTION — NO-DUE CERTIFICATE (if uploaded)
  Fields extracted:
    loan_account_number : Must match Mudra letter
    borrower_name       : Must match Mudra letter
    certificate_date    : Date of no-due certificate
    issuing_bank        : Must match Mudra letter bank
    loan_status         : Closed / Settled


INDIVIDUAL VALIDATION — PMMY
  Field               | Rule                                        | Blocking
  --------------------|---------------------------------------------|---------
  Loan Account Number | Alphanumeric, min 6 characters              | HARD FAIL
  Applicant Name      | Readable, min 3 chars                       | HARD FAIL
  Loan Amount         | Must be > 0 and ≤ ₹10,00,000 (Mudra limit) | HARD FAIL
  Loan Type           | Must be Shishu / Kishor / Tarun             | Soft flag
  Approval Date       | Must be a valid past date                   | Soft flag


CROSS-INTERNAL VALIDATION — PMMY
  Field                | Mudra Letter     | No-Due Certificate | Blocking
  ---------------------|------------------|--------------------|----------
  Loan Account Number  | Must match       | Must match         | HARD FAIL
  Applicant Name       | Source           | Must match         | HARD FAIL
  Bank Name            | Source           | Must match         | Soft flag


BANK TRANSACTION CROSS-CHECK — PMMY
  Rule 1: Loan disbursement credit in Step-3 CSV
          Amount: Mudra loan amount ± 10%
          Date  : Near loan_approval_date ± 15 days
  Rule 2: Monthly EMI repayments found as recurring debits
          Merchant: bank name / MUDRA / LOAN / EMI in narration
  If disbursement found → mudra_credited = true
  If EMIs found        → mudra_repaying = true (strong P3 positive)
  If no-due cert uploaded + loan status = Closed → mudra_closed = true


GLOBAL VALIDATION — PMMY
  Field           | Compared Against               | Blocking
  ----------------|--------------------------------|---------
  Applicant Name  | Step-1 Full Name (fuzzy ≥ 85%) | Soft flag
  Bank Name       | Step-3 Verified Bank Name      | Soft flag

Global profile update:
  verified_profile.gov_schemes.pmmy = true
  verified_profile.gov_schemes.mudra_loan_amount = 50000
  verified_profile.gov_schemes.mudra_closed = false

SCHEME 5 — PPF (PUBLIC PROVIDENT FUND)
===========================================================================

Score impact: "Can add up to 8 points"
Note: No verification API. Validation via OCR + bank cross-check.

INPUTS:
  Input 1 : PPF Account Number (Conditional Required)
            Format  : Alphanumeric
  Input 2 : PPF Passbook First Page (Conditional Required)
            Format  : JPG or PNG


OCR EXTRACTION — PPF PASSBOOK
  Fields extracted:
    account_holder_name : Name on passbook
    ppf_account_number  : Unique PPF account ID
    cif_number          : Customer Information File number
    bank_name           : Holding bank
    branch_name         : Branch name
    date_of_issue       : Passbook issue date
    ifsc_code           : Branch IFSC
    annual_contribution : Typical deposit amount (₹)
    maturity_date       : 15-year lock-in end date


INDIVIDUAL VALIDATION — PPF
  Field                | Rule                                          | Blocking
  ---------------------|-----------------------------------------------|---------
  PPF Account Number   | Alphanumeric, min 6 characters               | HARD FAIL
  OCR Account Number   | Must match entered account number            | HARD FAIL
  Account Holder Name  | Readable, min 3 chars                        | HARD FAIL
  Annual Contribution  | Must be ≥ ₹500 and ≤ ₹1,50,000 (PPF limits) | Soft flag
  Maturity Date        | Must be a valid future or past date          | Soft flag


CROSS-INTERNAL VALIDATION — PPF
  Check                                                | Blocking
  -----------------------------------------------------|----------
  PPF account number consistent across passbook pages  | HARD FAIL
  IFSC code format valid (11 characters)               | Soft flag


BANK TRANSACTION CROSS-CHECK — PPF
  Rule: Step-3 CSV must show quarterly or annual debit
        Amount: annual_contribution amount ± 10%
        Merchant narration: PPF / PUBLIC PROVIDENT / SBI PPF / HDFC PPF
  If bank match found → ppf_bank_verified = true (P4 savings signal)


GLOBAL VALIDATION — PPF
  Field                | Compared Against                  | Blocking
  ---------------------|-----------------------------------|---------
  Account Holder Name  | Step-1 Full Name (fuzzy ≥ 85%)    | Soft flag
  Bank Name            | Step-3 Verified Bank Name         | Soft flag
  IFSC Code            | Step-3 Verified IFSC (if same bank)| Soft flag

Global profile update:
  verified_profile.gov_schemes.ppf = true
  verified_profile.gov_schemes.ppf_contribution = 12000

SCHEME 6 — UDYAM / MSME REGISTRATION  ← NEWLY ADDED
===========================================================================

Score impact: "Can add up to 15 points"
Note: Strongest formal business signal — significantly boosts P7 for
      Vendor, Freelancer, and Skilled Tradesperson work types.

INPUTS:
  Input 1 : Udyam Registration Number (Conditional Required)
            Format  : UDYAM-XX-00-0000000 (19-character format)
            Example : UDYAM-TN-33-0012345
  Input 2 : Udyam Registration Certificate Upload (Conditional Required)
            Format  : PDF preferred; JPG or PNG accepted

UI BEHAVIOUR:
  User enters Udyam Registration Number → clicks Verify
  If API succeeds → Certificate upload becomes enabled
  If API fails    → Error shown, scheme marked unverified


API VERIFICATION — UDYAM / MSME
  Endpoint  : POST /gov/msme/udyam-verify
  MongoDB   : udyam_db
  Request   : { "udyam_number": "UDYAM-TN-33-0012345" }
  Response  : {
                "enterprise_name"      : "Ravi Kumar Enterprises",
                "udyam_number"         : "UDYAM-TN-33-0012345",
                "category"             : "Micro",
                "nic_activity"         : "Retail Trade",
                "registration_date"    : "2021-08-15",
                "state"                : "Tamil Nadu",
                "status"               : "Active",
                "major_activity"       : "Services",
                "verified"             : true
              }
  Possible status: Active | Cancelled | Suspended | Not Found
  Possible category: Micro | Small | Medium


OCR EXTRACTION — UDYAM CERTIFICATE
  Fields extracted:
    udyam_number          : 19-character registration number
    enterprise_name       : Registered business/enterprise name
    owner_name            : Proprietor / partner name
    nic_code              : National Industrial Classification code
    nic_activity          : Business activity description
    category              : Micro / Small / Medium
    major_activity        : Manufacturing / Services / Trading
    registration_date     : Date of Udyam registration
    state_code            : 2-letter state code embedded in number
    date_of_commencement  : Business commencement date
    enterprise_type       : Proprietorship / Partnership / OPC / LLP


INDIVIDUAL VALIDATION — UDYAM
  Field                 | Rule                                          | Blocking
  ----------------------|-----------------------------------------------|---------
  Udyam Number          | Must match UDYAM-XX-00-0000000 format        | HARD FAIL
                        | (regex: UDYAM-[A-Z]{2}-[0-9]{2}-[0-9]{7})    |
  State Code in Number  | 2-letter state code must be valid Indian state| HARD FAIL
                        | (e.g. TN = Tamil Nadu, MH = Maharashtra)      |
  API Status            | Must be Active                                | HARD FAIL
  Category              | Must be Micro, Small, or Medium               | HARD FAIL
  OCR Udyam Number      | Must match entered number exactly             | HARD FAIL
  OCR Enterprise Name   | Must match API enterprise_name (fuzzy ≥ 80%) | HARD FAIL
  Registration Date     | Must be a valid past date                     | Soft flag
  NIC Code              | Must be a valid 5-digit NIC code              | Soft flag
  Enterprise Type       | Must be valid legal entity type               | Soft flag


CROSS-INTERNAL VALIDATION — UDYAM
  Check                                                    | Blocking
  ---------------------------------------------------------|---------
  Udyam number on certificate must match entered number    | HARD FAIL
  State code in Udyam number must match state in address   | Soft flag
  Enterprise name consistent across all certificate sections| Soft flag
  Registration date must not be in the future              | HARD FAIL
  Category (Micro/Small/Medium) consistent across sections | Soft flag


BANK TRANSACTION CROSS-CHECK — UDYAM
  UDYAM registration has no direct payment/debit to check.
  However:
    Rule 1: If Step-5 has GST certificate with same GSTIN → cross-link
            gst_udyam_linked = true (strong P7 signal)
    Rule 2: Business income credits in Step-3 bank statement
            tagged as INCOME_GIG or INCOME_CASH may be cross-linked
            to Udyam activity type for income consistency scoring


GLOBAL VALIDATION — UDYAM
  Field               | Compared Against                       | Blocking
  --------------------|----------------------------------------|---------
  Enterprise Name     | Step-1 Full Name (fuzzy ≥ 80%)         | Soft flag
                      | (proprietor name may differ from biz   |
                      |  name — fuzzy match on owner_name used)|
  Owner Name          | Step-2 Aadhaar Name (fuzzy ≥ 85%)      | Soft flag
  State               | Step-1 State of Residence (exact)      | Soft flag
  Major Activity      | Step-1 Work Type alignment:            | Soft flag
                      |   Services → Freelancer / Tradesperson |
                      |   Trading → Vendor / Seller            |
  GSTIN Cross-link    | Step-5 GST cert GSTIN if available     | Soft flag
                      | If match → gst_udyam_linked = true     |

Example:
  Udyam owner_name   : Ravi Kumar
  Step-2 Aadhaar name: Ravi Kumar
  → fuzzy match ≥ 85% → PASS

  Udyam enterprise_name : Ravi Kumar Traders
  Step-1 Full Name      : Ravi Kumar
  → fuzzy match on owner_name used, not enterprise_name

Global profile update:
  verified_profile.gov_schemes.udyam = true
  verified_profile.gov_schemes.udyam_category = "Micro"
  verified_profile.gov_schemes.udyam_activity = "Services"
  verified_profile.gov_schemes.gst_udyam_linked = true

TECHNICAL FLOW — STEP-6
===========================================================================

User opens Step-6
  ↓
Score impact message displayed
  ↓
User sees 6 scheme cards (all collapsed by default)
  ↓
[FOR EACH SCHEME USER SELECTS]

  User taps scheme card → expands
  User enters scheme ID (UAN / pension account / Udyam number etc.)

    → API response stored temporarily
    → Document upload enabled on success

    → Individual validation: OCR fields vs API response
    → Individual validation: format rules on all fields
  Cross-internal validation: consistency within document
  Bank cross-check: scheme payment matched in Step-3 CSV
  Global validation: identity fields vs Step-1 / Step-2 / Step-3
  Scheme marked: verified = true / unverified = false
  ↓
[AFTER ALL SELECTED SCHEMES PROCESSED]

  Global profile updated with all scheme flags
  ML features computed: scheme_count_norm, scheme_bank_verified_ratio
  ↓
Step-6 Status = COMPLETED
  ↓
User proceeds to Step-7 — Insurance Verification
