PURPOSE
───────
This file defines every MongoDB database collection required to simulate
government verification APIs in the GigCredit onboarding system.
Each API endpoint fetches from one or more collections defined here.

Architecture:
  Backend   : FastAPI (Python)
  Database  : MongoDB (document store)
  Pattern   : Each government API = one or more MongoDB collections
  Seeding   : Collections are pre-seeded with mock/test records
  Response  : FastAPI queries collection → returns simulation response

DATABASE NAME: gigcredit_gov_sim_db

1. COLLECTION: aadhaar_db
   API: POST /verify-aadhaar
   Step: Step-2 (Identity KYC)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

PURPOSE:
  Simulates UIDAI Aadhaar verification database.
  API fetches record by aadhaar_number.
  Returns name, DOB, mobile, status for OTP + OCR cross-check.

SCHEMA:
  Field               | Type    | Required | Description
  --------------------|---------|----------|---------------------------------
  _id                 | ObjectId| Auto     | MongoDB document ID
  aadhaar_number      | String  | YES      | 12-digit Aadhaar (query key)
  name                | String  | YES      | Registered name (used for OCR match)
  date_of_birth       | String  | YES      | Format: YYYY-MM-DD
  gender              | String  | YES      | Male / Female / Transgender
  mobile              | String  | YES      | 10-digit registered mobile
  email               | String  | NO       | Registered email (optional)
  address             | Object  | YES      | Full address object (see below)
  photo_hash          | String  | YES      | Hashed face embedding reference
  status              | String  | YES      | active / inactive / locked
  created_at          | Date    | Auto     | Record creation timestamp
  updated_at          | Date    | Auto     | Last update timestamp

  address sub-document:
    house_number | street | area | city | district | state | pin_code

INDEXES:
  aadhaar_number : unique index (primary query field)
  mobile         : index (for OTP routing)

SAMPLE RECORD:
  {
    "aadhaar_number" : "123456789123",
    "name"           : "Ravi Kumar",
    "date_of_birth"  : "1997-06-12",
    "gender"         : "Male",
    "mobile"         : "9876543210",
    "address"        : {
      "house_number" : "No 14",
      "street"       : "Anna Nagar Main Road",
      "area"         : "Anna Nagar",
      "city"         : "Chennai",
      "district"     : "Chennai",
      "state"        : "Tamil Nadu",
      "pin_code"     : "600040"
    },
    "photo_hash"     : "sha256:a1b2c3d4...",
    "status"         : "active"
  }

API QUERY:
  db.aadhaar_db.findOne({ aadhaar_number: "123456789123" })

API RESPONSE (to app):
  { name, date_of_birth, mobile, status, otp_sent: true }

PURPOSE:
  Simulates Income Tax Department PAN verification database.
  API fetches by pan_number. Returns name, DOB, ITR filing status.

SCHEMA:
  Field              | Type    | Required | Description
  -------------------|---------|----------|---------------------------------
  _id                | ObjectId| Auto     | MongoDB document ID
  pan_number         | String  | YES      | 10-char PAN (ABCDE1234F format) — query key
  name               | String  | YES      | Name as per PAN
  date_of_birth      | String  | YES      | Format: YYYY-MM-DD
  father_name        | String  | YES      | Father's name as per PAN
  aadhaar_linked     | Boolean | YES      | Whether Aadhaar is linked
  itr_filed          | Boolean | YES      | Whether ITR was filed last AY
  itr_assessment_year| String  | NO       | e.g. "2024-25"
  status             | String  | YES      | Active / Inactive / Blocked
  created_at         | Date    | Auto     | Timestamp

INDEXES:
  pan_number : unique index (primary query field)

SAMPLE RECORD:
  {
    "pan_number"          : "ABCDE1234F",
    "name"                : "Ravi Kumar",
    "date_of_birth"       : "1997-06-12",
    "father_name"         : "Suresh Kumar",
    "aadhaar_linked"      : true,
    "itr_filed"           : true,
    "itr_assessment_year" : "2024-25",
    "status"              : "Active"
  }

API QUERY:
  db.pan_db.findOne({ pan_number: "ABCDE1234F" })

API RESPONSE (to app):
  { name, date_of_birth, status, itr_filed, itr_assessment_year }

PURPOSE:
  Simulates RBI IFSC code dataset.
  API fetches by ifsc_code. Returns bank name, branch, city, MICR.

SCHEMA:
  Field       | Type    | Required | Description
  ------------|---------|----------|---------------------------------
  _id         | ObjectId| Auto     | MongoDB document ID
  ifsc_code   | String  | YES      | 11-char IFSC code — query key
  bank_name   | String  | YES      | Full bank name
  branch_name | String  | YES      | Branch name
  address     | String  | YES      | Branch address
  city        | String  | YES      | City
  district    | String  | YES      | District
  state       | String  | YES      | State
  pin_code    | String  | YES      | 6-digit PIN
  micr_code   | String  | YES      | 9-digit MICR code
  upi_enabled | Boolean | YES      | UPI support flag
  rtgs_enabled| Boolean | YES      | RTGS support flag
  neft_enabled| Boolean | YES      | NEFT support flag

INDEXES:
  ifsc_code   : unique index
  bank_name   : index (for bank-level queries)

SAMPLE RECORD:
  {
    "ifsc_code"   : "HDFC0001234",
    "bank_name"   : "HDFC Bank",
    "branch_name" : "Anna Nagar",
    "address"     : "No 5, Anna Nagar Main Road, Chennai",
    "city"        : "Chennai",
    "district"    : "Chennai",
    "state"       : "Tamil Nadu",
    "pin_code"    : "600040",
    "micr_code"   : "600240012",
    "upi_enabled" : true,
    "rtgs_enabled": true,
    "neft_enabled": true
  }

API QUERY:
  db.ifsc_db.findOne({ ifsc_code: "HDFC0001234" })

API RESPONSE (to app):
  { bank_name, branch_name, city, state, micr_code }
